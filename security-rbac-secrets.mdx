## Topic

Kubernetes security separates authentication from authorization. RBAC grants permissions through Roles and RoleBindings, namespaces isolate resources, Secrets hold sensitive configuration, and ConfigMaps hold non-sensitive configuration.

## Commands to implement it

```bash
kubectl create namespace dev
kubectl create serviceaccount deployer -n dev
kubectl create role pod-reader --verb=get,list,watch --resource=pods -n dev
kubectl create rolebinding deployer-read --role=pod-reader --serviceaccount=dev:deployer -n dev
kubectl create secret generic app-secret --from-literal=API_KEY=replace-me -n dev
kubectl auth can-i get pods --as=system:serviceaccount:dev:deployer -n dev
```

## Output

```text
yes
```

<Warning>
  Do not commit real credentials to a manifest or source repository. Kubernetes Secrets provide controlled storage, but you must also configure appropriate encryption and access policies.
</Warning>

<Note>
  RBAC answers what an authenticated identity may do. Authentication answers who the identity is.
</Note>

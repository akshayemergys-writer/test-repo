Kubernetes resources are commonly described in YAML manifests. YAML makes the desired state reviewable and repeatable, while labels and selectors connect related resources.

The Deployment example runs `nginx:1.27`, a versioned Docker image containing the Nginx web server. The `image` field tells Kubernetes which packaged application to start; Kubernetes does not build that image from the YAML file.

## YAML manifest structure

Most objects use `apiVersion`, `kind`, `metadata`, and `spec`. The `data` field is used by objects such as ConfigMaps and Secrets.

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
  labels:
    app: web
    environment: demo
spec:
  replicas: 2
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
        - name: web
          image: nginx:1.27
          ports:
            - containerPort: 80
```

## Labels, selectors, and annotations

- **Labels** identify objects, such as `app: web` or `environment: demo`.
- **Selectors** find objects with matching labels. A Deployment selector must match its Pod template labels.
- **Annotations** store metadata for tools and integrations, but they are not normally used to select workloads.

Use labels to group workloads by application, team, environment, or version. Use selectors to make a Service target only the intended Pods.

## ConfigMaps and configuration

ConfigMaps hold non-sensitive values such as feature flags, log levels, or environment names. Mount them as files or expose them as environment variables so the same image can run in multiple environments.

## Commands to implement it

```bash
kubectl apply -f deployment.yaml
kubectl get pods --show-labels
kubectl get pods -l app=web
kubectl label pod web-demo environment=dev
kubectl annotate deployment web owner=platform
kubectl create configmap app-config --from-literal=MODE=development
kubectl get configmap app-config -o yaml
```

Example manifest:

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
  labels:
    app: web
data:
  MODE: development
```

<Note>
  YAML indentation matters. ConfigMaps are not designed for passwords or keys; use Secrets for sensitive values. For persistent application data, continue to [Storage: PV and PVC](/storage-pv-pvc).
</Note>
